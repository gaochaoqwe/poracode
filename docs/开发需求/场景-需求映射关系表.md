> 本表用于核对「需求文档的每个 agent 场景是否都有对应的 AgentEmployee 场景入口」。
> 若后续增删场景，请同步更新本表。

## 一、覆盖状态定义

| 状态 | 含义 |
| --- | --- |
| **已覆盖** | 已作为场景入口（侧边栏「场景」分组 + 草稿步骤引导），点击即可用。 |
| **需定制** | 已建场景入口并提供流程引导，但需要 AgentEmployee 尚未具备的能力（插件 / 定制模块 / 配置页）。场景的引导卡片和侧边栏按钮会显示「需要定制」标记。 |
| **复用现有** | AgentEmployee 已有能力（权限/计划中断、编辑器/diff），无需独立场景按钮。 |

## 四、两份需求之外的扩展场景

以下场景在两份需求中没有对应条目（两份需求未包含独立的「测试智能体」文档），系本项目按开发人员实际需要额外补充：

| 分组 | 场景 id | 名称 | 说明 |
| --- | --- | --- | --- |
| 软件编码 | `write-unit-tests` | 单元测试 | 开发人员使用的单元测试编写场景。 |
| 软件编码 | `modify-project-code` | 工程级代码修改 | 工程级功能新增 / 行为变更，先出改动方案再按现有架构落地。 |
| 软件编码 | `fix-coding-rule-issues` | 编码规则问题修复 | 修复 lint / 格式化 / 编码规则违规，保持行为不变。 |
| 软件测试 | `review-document` | 文档审查 | 面向测试人员的文档审查。 |
| 软件测试 | `static-analysis` | 静态分析 | 静态分析查缺陷。 |
| 软件测试 | `code-review` | 代码审查 | 以测试视角审查代码。 |
| 软件测试 | `generate-test-cases` | 用例生成 | 由需求/接口生成测试用例。 |

## 五、需定制清单（6 个）

这些场景已提供入口与流程引导，引导卡片和侧边栏会标注「需要定制模块或插件」。落地所需能力见下：

| 场景 id | 名称 | 所需能力 |
| --- | --- | --- |
| `trace-requirement-design` | 需求-设计追踪 | 追溯矩阵存储 + 覆盖率可视化页面 |
| `detect-related-changes` | 关联检出与联动修改 | 追溯图联动 UI（依赖上一项） |
| `import-document` | 文档导入与解析 | 文档解析 MCP 插件（docx/pdf/表格） |
| `export-document` | 按模板导出文档 | 文档转换服务 + 模板管理页面 |
| `knowledge-search` | 知识库检索 | 向量库 MCP 插件 + 引用标注 |
| `configure-knowledge-base` | 知识库配置 | 连接配置页面（平台设置） |

## 六、平台侧能力（不建场景入口）

两份需求文档第三节均将其列为平台层实现，与 agent 技能无关，故不建场景入口：

- 登录（本地 / 在线）
- 并发访问与空间隔离（含「500 并发」等非功能指标）
- 备份与回退（手动长期备份 / 自动短期备份 / 版本回退）
- 日志管理（系统日志 / 智能体工作日志）
- 数据统计与上报
- 模型密钥加密存储与脱敏
- 强化学习反馈上报
- VS Code / code-server 插件宿主形态（AgentEmployee 等价为桌面端工作区 + 聊天线程 + 文件编辑/diff）
- 知识库配置与检索的后端服务（前端入口已作为 `configure-knowledge-base` / `knowledge-search` 场景列出，标注需定制）
