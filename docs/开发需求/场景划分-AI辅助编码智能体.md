# 使用场景划分：AI辅助编码智能体（CODE-AGENT）

> 配套需求文档：《AI辅助编码智能体软件需求规格说明书0824.md》
> 目的：把需求文档拆成一个个「用户能用 AgentEmployee + 某个 agent 直接完成」的具体场景，作为后续开发 skill / plugin / 定制模块的依据。

## 一、范围说明

- 本文只划分 **agent 可执行** 的场景（工程理解 / 代码生成 / 修复优化 / 追溯 / 编辑）。
- 纯平台基础能力（登录、知识库配置、备份回退、日志、统计上报、并发与空间隔离等）不展开，统一列在文末「平台侧能力」。
- 需求文档要求「以 VS Code 插件形式存在」，落到 AgentEmployee 上等价为 **桌面端工作区（打开工程目录）+ 聊天线程 + 文件编辑/diff + 权限/计划中断**；VS Code / code-server 宿主形态属平台侧。

### 实现形态图例

| 形态 | 含义 | 判定依据 |
| --- | --- | --- |
| **Skill** | 一个 `SKILL.md`，纯流程/规则/模板知识，模型推理 + 读写文件即可完成 | 不需要外部服务或进程 |
| **Plugin** | Agent Plugins 包（`plugin.json` + skill + `mcp.json`），给 skill 挂外部工具 | 需要文档解析、代码索引、构建/校验等工具 |
| **定制模块 / 页面** | supervisor / renderer 里新增代码与 UI | 需要结构化持久化、可视化页面、变更集管理 |
| **复用现有** | AgentEmployee 已具备，无需新开发 | 编辑器/diff 审阅、权限与计划中断、附件导入、provider 配置 |

## 二、使用场景

| # | 场景 | 一句话描述 | 输入 → 输出 | 推荐实现形态 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 1 | 代码工程理解与描述生成 | 扫描已打开工程，产出工程描述摘要 | 工程目录 → 项目类型/框架/语言、符号清单、编码风格摘要 | **Skill**（+ 可选代码索引 MCP） | 复用文件/grep/终端；大工程可再挂符号索引 MCP |
| 2 | 函数级/片段级代码生成 | 在现有工程内生成风格一致、接口兼容的函数/片段 | 工程上下文 + 自然语言描述 → 函数/片段代码 | **Skill** | 核心场景。skill 规定「先出接口框架 → 确认 → 完整实现」，并约束沿用现有风格 |
| 3 | 工程级代码生成 | 从需求/设计 + 框架模板生成完整可编译工程 | 框架模板/空白模板 + 需求/设计/接口 + 语言风格 → 工程骨架 + 全部源文件 + 配置 + 构建脚本 | **Skill**（+ 可选脚手架 Plugin） | skill 规定「理解框架 → 骨架 → 逐模块生成 → 构建脚本」；脚手架模板可做成 plugin 资源 |
| 4 | 代码质量检查 | 逐行 + 跨文件检查语法/接口一致性/异常覆盖/命名/安全 | 代码 + 规范 → 问题清单（定位到行号/类型/严重度） | **Skill** + 内置工具（lint/静态分析） | 规则与输出格式写进 skill；实际检查复用 AgentEmployee 运行 lint/编译的能力 |
| 5 | 代码缺陷定位与修复 | 由错误描述/日志/堆栈定位缺陷并产出补丁 | 代码 + 日志/堆栈 → 定位结果 + 修复补丁 + 依据 | **Skill**（+ 复用编辑器/diff） | skill 规定「解析日志 → 定位 → 补丁 → 待确认」；应用补丁复用现有编辑流程 |
| 6 | 代码优化与重构 | 按性能/可读性/可维护性目标产出优化版本 | 代码 + 优化目标 → 优化代码 + 前后差异 + 说明 | **Skill**（+ 复用 diff 审阅） | 强制功能等价、逐项采纳、可回退，写进 skill 约束 |
| 7 | 需求/设计与代码双向追溯 | 建立需求/设计条目 ↔ 代码文件/函数的正反向追溯 | 需求/设计条目 ID、代码路径/函数 → 追溯图 + 覆盖率 | **Skill**（记录来源）+ **定制模块**（追溯矩阵/反查 UI） | 关系需要结构化存储与可视化页面，超出 skill 能力 |
| 8 | 关联检出与智能修改建议 | 改一处后列出受影响的调用点/接口并给建议 | 被改文件/函数 → 关联位置列表 + 影响分析 | **Skill**（+ 依赖图工具） | 基础版靠 grep/read；深度直接调用分析可挂代码依赖图 MCP |
| 9 | 在线编辑 | 在编辑器中直接修订生成的代码 | 用户编辑操作 → 更新后的代码 + 版本记录 | **复用现有** | AgentEmployee 已有文件编辑与 Changes/diff 审阅，无需新开发 |
| 10 | 变更集 / 补丁 / 代码包导出与基线提交 | 整理变更集、导出补丁或工程包、提交基线 | 变更范围 + 目标 → 变更集/补丁/代码包 | **定制模块** | 需要变更集管理、打包、导出与基线提交页面 |
| 11 | 文档与接口文件解析导入 | 上传需求/设计/接口/头文件，抽取结构化信息 | 本地文档/代码文件 → 结构化需求/设计/接口 | **Plugin**（文档解析 MCP） | 上传复用现有附件能力；解析需要外部解析引擎 |
| 12 | 执行中断与用户授权 | 关键节点（写文件前、覆盖前）自动暂停待确认 | 中断点 + 现场 → 授权界面 + 恢复执行 | **复用现有**（Permission / Plan 中断）+ **Skill** | AgentEmployee 天然支持权限/计划中断；skill 规定「文件写入/覆盖/接口变更必须停下」 |

## 三、平台侧能力（本轮不做，单列）

登录（本地/在线）、知识库配置与检索（可与需求分析智能体共用）、备份与回退、日志管理、数据统计与上报、并发访问与空间隔离、模型密钥加密存储、VS Code / code-server 插件宿主形态、强化学习反馈上报等 —— 与 agent 技能无关，需平台层单独实现。

## 四、落地优先级建议

1. **P0（纯 skill，最快见效）**：场景 1、2、5、6 —— 直接产出 `SKILL.md`，无需新代码。
2. **P1（skill + 现有工具）**：场景 3、4、8、12 —— 依赖编辑器/diff、权限中断、lint 等已有能力。
3. **P2（需 plugin / MCP）**：场景 11（+ 场景 1/8 的增强）—— 需要文档解析、代码索引工具。
4. **P3（需定制模块/页面）**：场景 7、10 —— 需要追溯矩阵、变更集与导出页面。
