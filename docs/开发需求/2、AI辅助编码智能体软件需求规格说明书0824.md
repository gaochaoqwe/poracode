## 系统概述

### 系统组成及功能概述

AI辅助编码智能体面向软件研发编码阶段，提供从需求、设计、接口文件、自然语言描述和现有工程到代码生成、补丁修改、工程级实现、代码修复、代码优化重构和变更集管理的能力。该智能体可独立部署、独立运行、独立使用，本智能体以VS Code插件形式存在，支持集成到code-server以及客户端版本的VS Code中，可在Windows、Linux环境下使用。本智能体通过以太网接口与AI研发平台交互，同时预留网络通信接口，支持后续与上下游协作平台（软件工厂等）进行交互。系统外部交互关系如下图所示。


图4 工程级代码生成工作流程图

1. **登录与环境准备：用户通过VS Code插件登录系统，配置模型参数与系统提示词，连接知识库；**
2. **选择工程级代码生成模式：用户在插件中选择"工程级代码生成模式"，系统引导用户指定开发框架路径（服务器上的框架模板路径）或选择空白工程模板，输入目标编程语言、编码风格偏好和工程结构描述，系统执行框架结构理解并生成框架结构摘要，经用户确认后锁定生成模式配置；**
3. **导入与解析：导入软件需求、设计文档、接口文件等，系统自动解析并提取结构化信息（需求条目、设计约束、接口定义），关键节点中断等待用户确认；**
4. **知识检索增强：基于导入材料检索知识库（操作系统接口知识库、驱动接口知识库、软件CBB知识库等），获取可复用的代码模板和设计模式；**
5. **工程骨架生成：系统结合导入材料、用户提示词与检索结果，首先生成工程目录结构、模块分解方案、核心接口定义和配置文件框架，逐轮向用户澄清技术选型、模块划分、接口参数、异常处理等缺失信息，经用户确认后锁定工程骨架；**
6. **逐模块代码生成：系统按模块分解方案逐模块生成完整代码实现，每个模块生成后中断等待用户审查确认，用户确认后方进入下一模块；所有模块完成后生成构建脚本和工程说明文档；**
7. **代码质量检查：系统检查生成代码的语法正确性、接口一致性、异常处理覆盖、命名规范性和安全性问题，问题定位到具体行号，输出问题清单供用户确认修订或驳回；**
8. **在线编辑与完善：用户在VS Code编辑器中在线修订代码，系统关联检出受影响的函数调用和接口定义提示联动修改；**
9. **版本管理：系统自动形成短期版本，用户可随时手动保存长期备份或回退至指定版本；**
10. **建立追溯与提交基线：系统建立需求/设计条目到代码文件/函数的双向追溯关系，用户确认后整理变更集提交平台建立基线；**
11. **导出与入库：按项目文件结构导出完整代码工程，上报平台归档，高质量代码片段入库沉淀**。

## 基于现有代码的函数级/片段级代码生成

本场景适用于用户已有部分代码工程或框架，需在现有代码基础上生成特定函数、模块或代码片段，以实现新增功能、接口适配或缺陷修复的场景。工作流程如下图所示。

图5 基于现有代码的函数级/片段级代码生成工作流程图

1. **登录与环境准备：用户通过VS Code插件登录系统，配置模型参数与系统提示词，连接知识库，打开或导入现有代码工程；**
2. **选择函数级/片段级代码生成模式：用户在插件中选择"函数级/片段级代码生成模式"，系统校验当前已打开VS Code工程并已完成代码工程理解，若未完成则自动触发或引导用户执行工程扫描，加载已建立的工程描述摘要供用户确认；**
3. **代码上下文解析：系统扫描并解析当前工程的目录结构、模块边界、现有函数签名、类定义、接口声明、依赖关系和编码风格，建立代码上下文索引，识别待扩展的插入点和关联接口，关键节点中断等待用户确认解析结果；**
4. **目标功能描述与澄清：用户通过自然语言或交互方式描述待生成的函数/模块功能需求，包括输入输出参数、业务逻辑、异常处理要求等，系统逐轮澄清缺失信息，明确生成范围及与现有代码的集成方式；**
5. **知识检索增强：基于用户描述和代码上下文检索知识库（操作系统接口知识库、驱动接口知识库、软件CBB知识库等），获取可复用的代码模板和设计模式；**
6. **代码生成：系统结合代码上下文、用户描述与检索结果，首先生成函数/模块的接口定义和逻辑框架，经用户确认后生成完整的代码实现，生成内容遵循现有工程的编码风格和命名规范；**
7. **代码质量检查：系统检查生成代码的语法正确性、与现有接口的兼容性、异常处理覆盖和安全性问题，问题定位到具体行号，输出问题清单供用户确认修订或驳回；**
8. **在线编辑与完善：用户在VS Code编辑器中在线修订代码，系统关联检出受影响的函数调用和接口定义提示联动修改；**
9. **版本管理：系统自动形成短期版本，用户可随时手动保存长期备份或回退至指定版本；**
10. **建立追溯与提交：系统建立需求/设计条目到新增代码文件/函数的双向追溯关系，用户确认后整理变更集提交平台归档。**

## 代码生成模式选择

### 函数级/片段级代码生成模式

a)标识号：CODE-AGENT-MODE-001

b)说明：选择函数级/片段级代码生成模式，该模式适用于用户在已有代码工程基础上新增、修改或扩展现有功能的场景。系统基于当前打开的VS Code工程上下文、已执行的代码工程理解以及用户自然语言描述的功能需求，生成与现有代码风格一致、接口兼容的单个函数或代码片段。该模式下，系统不创建新的工程结构，仅在现有工程范围内完成代码的增补与修改。

c)输入：

1. 当前VS Code工作空间上下文；
2. 当前打开的VS Code代码工程及已建立的工程描述摘要；
3. 共用的知识库检索结果（软件CBB、操作系统接口、驱动接口等。

d)输出：模式确认状态、生成范围界定（新增/修改/扩展现有代码）、待澄清问题列表。

e)处理过程：

1. 用户通过VS Code插件选择"函数级/片段级代码生成模式"；
2. 系统校验当前是否已打开VS Code工程，若未打开则提示用户先打开工程；
3. 系统校验当前工程是否已完成代码工程理解，若未完成则自动触发或引导用户执行工程扫描；
4. 系统加载已建立的工程描述摘要（含项目类型、编程语言、目录结构、符号清单、编码风格摘要等），向用户展示当前工程上下文概览并等待确认；
5. 用户确认工程上下文无误后，在对话窗口中用自然语言描述待实现的功能需求；
6. 系统依据工程描述摘要和用户描述，通过功能描述与代码映射检索已有符号，判断是否存在可复用的接口或类似实现，避免重复生成；
7. 系统识别功能描述中不明确的信息（如输入输出参数类型、异常处理策略、与其他模块的依赖关系等），生成待澄清问题列表向用户提问；
8. 用户逐项确认或补充后，系统完成模式配置，进入代码生成流程。

f)约束和限制：

1. 本模式下用户必须先打开VS Code工程；
2. 本模式下系统必须能够获取当前工程的代码上下文（工程描述摘要）；
3. 用户可通过自然语言持续对话细化功能需求，系统支持多轮交互；
4. 模式切换后，已配置的信息和已生成的中间结果应予以保留或提示用户重新开始。

### 工程级代码生成模式

a)标识号：CODE-AGENT-MODE-002

b)说明：选择工程级代码生成模式，该模式适用于用户已有软件需求规格、软件设计文档或接口文件，需从零生成完整、可编译、可运行软件工程的场景。系统基于用户指定的开发框架路径或空白工程模板，首先理解框架的目录规范、模块划分、构建方式和编码风格，再结合用户提供的需求/设计材料，生成完整的工程骨架、全部源文件、配置文件和构建脚本。

c)输入：

1. 用户指定的开发框架路径或空白工程模板路径（服务器上的框架模板路径）；
2. 用户输入的目标编程语言、编码风格偏好、工程结构描述（如分层架构、模块划分要求等）；
3. 软件需求文档、软件设计文档或接口文件；
4. 共用的知识库检索结果（软件CBB、操作系统接口、驱动接口等）。

d)输出：模式确认状态、框架结构摘要、待澄清问题列表。

e)处理过程：

1. 用户通过VS Code插件选择"工程级代码生成模式"；

3. 系统执行框架结构理解，扫描框架模板的目录结构、识别构建系统（如CMake、Maven等）、提取框架的模块划分规范和典型代码组织方式，生成框架结构摘要；
4. 系统提示用户输入目标编程语言、编码风格偏好和工程结构描述（如分层架构、模块命名规则等）；
5. 系统向用户展示框架结构摘要和配置信息，对识别不明确或与用户描述不一致的内容输出待澄清问题列表，用户逐项确认或修正；
6. 用户确认后，系统引导用户导入软件需求、设计文档或接口文件（若尚未导入），或确认已导入的材料；
7. 系统完成模式配置，进入工程级代码生成流程。

f)约束和限制：

1. 本模式下用户必须指定有效的开发框架路径或工程模板路径；
2. 系统对框架结构的理解能力取决于框架模板的规范性和完整性，对自定义程度过高的框架可能需要用户补充说明；
3. 本模式下系统需同时具备对需求/设计材料的理解能力和对框架结构的理解能力；
4. 模式切换后，已配置的信息和已生成的中间结果应予以保留或提示用户重新开始；
5. 框架模板路径为服务器上的目录路径，由用户或管理员预先准备和维护。

d)输出：工作日志记录，支持展示和查询。

e)处理过程：

1. 拦截智能体运行过程中的所有消息传递；

2. 对每条消息添加时间戳、消息类型、会话ID；

3. 存储至结构化数据库；

4. 提供查询接口供前端展示或筛选。

f)约束和限制：工作日志中的敏感信息（如API Key）需自动脱敏处理；日志保留时间不少于30天。

### 智能体工作日志显示控制

a)标识号：CODE-AGENT-LOG-003

b)说明：提供界面按钮，让用户控制是否在对话窗口中显示智能体工作日志。适用于不同用户对日志详细程度有不同偏好的场景。

c)输入：用户点击"显示日志"或"隐藏日志"按钮。

d)输出：对话窗口中工作日志区域的显示/隐藏状态切换。

e)处理过程：

1. 用户在对话界面点击日志控制按钮；

2. 系统切换日志区域的显示状态；

3. 显示状态下，实时推送并渲染工作日志消息；

4. 隐藏状态下，停止推送日志但仍后台记录。

f)约束和限制：日志显示状态下仅展示最近200条；详细日志须按权限开启，不得对普通用户默认暴露敏感参数。

## 数据统计与上报功能

### 智能体数据统计

a)标识号：CODE-AGENT-STAT-001

b)说明：智能体自动统计任务总耗时、各步骤耗时、模型调用次数、输入输出Token数、工具调用次数、失败重试次数。适用于成本监控和性能分析的场景。

c)输入：智能体运行过程中的调用事件。

d)输出：结构化统计数据，存储至数据库。

e)处理过程：

1. 监听智能体执行链路中的每次模型调用和工具调用；

2. 累积计数并统计Token消耗；

3. 按时间维度（小时/天/周）聚合统计数据；

4. 提供查询接口供前端展示统计仪表盘。

f)约束和限制：统计数据更新延迟不超过5分钟；Token统计需区分输入和输出，分别记录。

### 数据上报

a)标识号：CODE-AGENT-STAT-002

b)说明：通过网络接口将统计信息定期或按需上报至AI研发平台。适用于平台级成本归集和资源监控的场景。

c)输入：上报周期（定时触发）或上报请求（即时触发）。

d)输出：上报成功状态及平台确认信息。

e)处理过程：

1. 按配置周期（默认每小时）触发数据上报任务；

2. 从统计数据库查询待上报时间段的数据；

3. 将数据封装为标准JSON格式；

4. 通过安全通道发送至AI研发平台指定接口；

5. 记录上报结果，失败时进入重试队列。

f)约束和限制：支持重试机制（最多3次，指数退避）；上报接口需支持批量上报（最多1000条/次）。

## 并发访问与空间隔离功能

### 并发访问

a)标识号：CODE-AGENT-CONC-001

b)说明：支持多用户同时访问系统，最大并发用户数不低于500。系统通过任务队列和限流策略保障高并发下的服务稳定性。

c)输入：多个用户的并发HTTP/WebSocket请求。

d)输出：各请求的独立响应结果、排队状态提示、限流告警信息。

e)处理过程：

1. 系统采用无状态服务架构，支持水平扩展，将并发请求纳入任务队列；

2. 使用连接池和线程池管理资源分配，按限流和资源配额调度任务；

3. 对排队任务输出排队状态和预计等待时间提示；

4. 监控实时并发数，超过阈值时排队或返回友好提示；

5. 提供在线人数、运行任务数、排队任务数和资源利用率统计接口。

f)约束和限制：

1. 500并发下平均响应时间不超过3秒；

2. 需支持自动扩容和负载均衡；

3. 并发与限流策略以AI研发平台配置为准；

4. 不得因单任务长耗时阻塞其他用户界面。

### 空间隔离

a)标识号：CODE-AGENT-CONC-002

b)说明：不同用户之间的工作空间完全隔离，用户只能访问和操作自己工作空间内的数据。系统按用户、项目和组织建立独立工作空间，隔离上传文件、会话、任务结果、临时文件、代码工程和知识库访问。

c)输入：用户访问请求（含用户身份凭证）、资源访问操作（上传文件、创建会话、查询任务结果、代码工程操作、知识库检索等）。

d)输出：仅包含该用户工作空间范围的数据、资源访问校验结果、临时目录清理记录。

e)处理过程：

1. 用户登录后建立会话，确定用户身份及所属项目和组织；

2. 系统按用户、项目和组织建立独立工作空间，为每个工作空间分配唯一标识；

3. 所有数据操作请求均携带用户标识和工作空间标识；

4. 数据访问层自动添加工作空间过滤条件，对跨工作空间访问进行权限校验并拦截；

5. 临时目录按任务生命周期自动清理，形成清理记录。

f)约束和限制：

1. 不同工作空间数据不得相互越权访问；

2. 管理员账户拥有跨空间只读权限（需审计）；

3. 空间隔离禁止通过任何API绕过；

4. 临时目录须按任务自动清理，不得残留跨会话数据。

# 非功能需求

本节仅列AI辅助编码智能体特有的非功能需求；系统认证身份并分配角色权限、工作空间隔离、安全审计、并发与任务队列、系统统计运行并度量成本、配置导入导出与开放接口、人工审查与中断恢复等共性基础能力见 2.8。

## 性能需求

a）性能需求1：工程索引和上下文切分应支持分块处理、函数级切分、增量索引和进度回传，避免大工程分析时间过长。

b）性能需求2：代码生成和路径分析应设置上下文预算、调用路径深度、文件数量和工具执行时间限制，降低上下文过长和路径分析空间爆炸风险。

c）性能需求3：代码生成、代码修复、工具执行和结果回传应记录 Token、耗时、工具调用和失败重试，支持平台成本统计。

## 易用性需求

a）易用性需求1：用户应能在专用页面、Windows、Linux环境下的 VS Code 插件或已集成该插件的 code-server 中查看编码目标、工程计划、代码差异、代码修复结果和变更集。

b）易用性需求2：所有 AI 生成、修改和审查结果均应提供依据、风险提示、差异展示和人工采纳入口。

c）易用性需求3：支持手动导入需求、设计、接口和代码上下文，支持手动导出补丁、说明、修复结果和入库数据包。

## 可靠性需求

a）可靠性需求1：任务失败时应保留目标梳理结果、工程计划、已生成补丁、工具输出和最近人工检查点，支持恢复。

b）可靠性需求2：代码修改、代码修复和回传失败时，应给出明确失败原因、可重试建议和人工处理建议。

c）可靠性需求3：变更集应支持版本保存和差异追踪，避免覆盖用户已有未提交变更。

d）可靠性需求4：智能体应支持将代码修复结果、用户采纳记录、修改意见和评分通过平台 API 上报，并预留偏好数据、样本标识、采纳结果和评分字段，保证反馈数据可追溯、不丢失；强化学习框架由用户平台选择和承载，本智能体不实现训练管理。
