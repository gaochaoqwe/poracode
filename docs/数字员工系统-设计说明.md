# 数字员工系统 · 设计说明

> 本文档为「数字员工」多智能体协作系统的完整设计说明，供后续开发与协作使用。基于 `poracode`（AgentEmployee 定制版）构建。

---

## 1. 项目背景

`poracode` 仓库是基于开源项目 **AgentEmployee**（Electron 桌面应用，用于编排多个 AI 编码代理）的定制版本，已内置「场景」功能（`src/renderer/scenarios/catalog.ts`，共 26 个场景入口），支持按 **GJB 438C** 标准生成软件需求规格说明书、软件设计说明、影响域分析报告等文档（配合内置 skill 和 docx 模板）。配套文档在 `docs/`（两份智能体需求规格说明书、场景划分、研制任务书等）。

## 2. 目标系统（数字员工系统）

在 AgentEmployee 基础上构建一套「数字员工」多智能体协作系统，模拟一个**软件测评组织**的运作。

### 组织分层

| 层级 | 性质 | 角色 | 说明 |
| --- | --- | --- | --- |
| 管理层 | 永久员工（常驻不释放） | 项目主管、测试主管，后续还有行业专家 | 长期存在，跨项目服务 |
| 执行层 | 临时工（每个项目一套完整团队，项目做完即释放） | 各节点执行员工 | 初期只设计一套执行层团队 |

### 关键约束与机制

- **并行能力**：初期同一时间只能并行 1 个项目（只有一套执行层团队）。需提供「复制团队」功能，后续用户直接复制一份执行层团队即可并行多个项目。
- **全局记忆系统**：需要升级（可调研现有开源项目作为参考）。
- **员工通信机制**：员工之间的通信机制待明确设计。
- **行业专家**：属于员工系统的一部分，**暂不实现**。后续规划：每个软件类别配一级专家、按产品配二级专家；测试主管会向行业专家咨询参考资料准备等问题。

## 3. 核心机制 —— 文件系统流转算法

文件系统是员工之间协作的**唯一载体**。

- 每个项目的每个节点（工作步骤）都对应真实文件系统中的一个文件夹；
- 每个数字员工**只操作属于自己的文件夹**；
- 文件名前缀代表状态，格式为「[节点-状态]」，例如：文档审查节点开始后文件名为「[文档审查-进行中]」，完成后为「[文档审查-已完成]」；
- **节点未开始前员工收不到任何文件**；
- 如果文件已流转到该员工但员工正忙于其他项目，文件保持上一节点完成时的状态**原地等待**；
- 员工根据自己收到文件的当前状态判断**何时开始、何时结束**。

> 以上就是文件、员工、节点、连线之间的流转规则。

### 测试主管的附加职责

测试主管（不是项目主管）在**项目开始前准备项目参考资料**（组织资产、其他项目资料等），供后续各节点员工参考。

## 4. 文件夹结构（模拟公司电脑本地文件夹）

顶层分三大类：`测试项目`、`开发项目`、`办公项目`，各类下分 `2025`、`2026` 年份目录。

### 4.1 测试项目

年份目录下外层包一层**状态目录**：

- `未开展`：用户放入新项目；
- `进行中`：测试主管从「未开展」中移入；
- `已完成`：测试主管认为项目完成移入。

状态目录下第一层按**软件类型**分十类：

1. 一系统控制类
2. 二随动控制类
3. 三图像处理类
4. 四温补调焦类
5. 五激光类
6. 六红外类
7. 七手柄类
8. 八分色滤光类
9. 九外部测试
10. 十搜潜

其中**一~八类下再分子类**：`1光雷`、`2吊舱`、`3转塔`、`4告警`、`5地防`；**九、十类直接按具体项目名称分**。

#### 测试项目内部流程（P0~P14）

每个测试项目内部按流程建 P0~P14 子目录：

| 节点 | 目录名 | 执行人 / 说明 |
| --- | --- | --- |
| P0 | P0-测试申请文件 | 内含 `组织资产` / `参考资料` / `本项目资料` 三个子目录 |
| P1 | P1-准入审查 | 项目主管执行，只审查资料齐套性：配置项测试需需求规格说明+代码；回归测试需影响域分析报告+变更前后两版代码。输出 通过/不通过 |
| P2 | P2-测试策划 | 测试主管执行，输出「XXX配置项/配置项回归测试表单2.00.00」，版本号不固定随项目；需调用内网工具，该岗位能力待完善 |
| P3 | P3-文档审查 | — |
| P4 | P4-静态分析 | — |
| P5 | P5-代码审查 | — |
| P6 | P6-动态测试-用例设计 | — |
| P7 | P7-动态测试-用例执行 | — |
| P8 | P8-动态测试-用例修正 | — |
| P9 | P9-动态测试-问题单生成 | — |
| P10 | P10-表单质量检查 | — |
| P11 | P11-报告生成 | — |

| P13 | P13-报告质量检查 | — |
| P14 | P14-最终报告 | — |

### 4.2 开发项目

年份目录下**直接放项目文件夹**（如 2026 下：`AI软件测评-web版`、`AI辅助软件研发-3个智能体web版`、`数字员工`），**无状态层、无 P 流程**。

### 4.3 办公项目

年份目录下最外层为**状态目录**（未开展/进行中/已完成），之下按分类放：

- `分类1（中心项目）`
- `分类2（部门项目）`
- `分类3`

### 员工工作区规则

每个员工是哪个类别的员工，就在对应的大文件夹下工作。

## 5. 落地动作（已确认）

在 poracode 仓库内创建模拟公司电脑本地文件夹的**完整目录树**（测试项目的十个类型 × 五个子类 × 三种状态、开发/办公项目的目录），并提交到 git；用一个示例测试项目展示 P0~P14 内部结构。

目录树位于仓库根目录：`模拟公司电脑文件夹/`。
