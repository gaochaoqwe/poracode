### 动态子节（subsections）写法

每个子节是 `{ "name": …, "content": … }`，可**递归**再嵌套 `subsections`，并可用 `blocks` 承载**正文段**与**设计表**：

- `name`：子节标题（引擎自动加章节号，如 `5.3.1 词法分析器`，不要自己写编号）。
- `content`：该子节的正文；按 `\n` 拆成多段。无正文可省略（但不得与 `blocks` 同时为空）。
- `blocks`：有序数组，元素为
  - `{ "type": "para", "text": "<一段正文>" }`
  - `{ "type": "table", "prototype": "<表原型名>", "caption": "表<N>-X <表标题>", "data_start_row": 1, "preserve_tail_rows": 0, "rows": [ { "<列键>": "值", … } ] }`
- `subsections`：更深一层子节（如 `5.3.1` 下的 `5.3.1.1 入口函数`）。

**表原型名（`prototype`）按章节固定**，只能使用下列名字：

| 章节 | 可用 `prototype`（列键）                                                                                                                                                                                                                                                                                            |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4.1  | `unit_list`(number,csc,csu,identifier,reuse)；`unit_alloc`(id,alloc_type,requirement)                                                                                                                                                                                                                               |
| 4.2  | `task_desc`(number,name,priority,identifier,description)；`irq_desc`(number,name,type,priority,identifier,description)；`task_calls`(number,task_identifier,units,note)；`exec_rule`(name,content)                                                                                                                  |
| 4.3  | `data_elem`(number,if_id,name,dimension,range,precision,var_id,data_type)；`data_group`(number,if_id,name,elements,definition)；`comm`(number,if_id,object,link,message,period,priority)；`protocol`(number,if_id,validity,packing,sync)                                                                            |
| 5    | `entry_func`(item,content)；`io_data`(number,name,identifier,type,length,direction,description)；`local_var`(number,name,identifier,type,length,dimension,description)；`struct_def`(struct_id,element,identifier,type,dimension,range)；`rule_algo`(name,content)；`error_handle`(number,error,detection,handling) |

表块规则：

- `rows` 每行的键集合**必须严格等于**该原型列键（多、少、拼错都会报错）。
- **单元格不得为空**——没有内容写 `无` 或 `-`（引擎拒绝空串）。
- 表标题用 `caption`，写成 `表<章号>-X <标题>`（如 `表5-X 词法分析器入口函数`），引擎按第三章号自动重排为 `表5-1 …`。表数据的来源是需求/源码，**不得臆造**。

示例（第 5 章一个单元）：

```json
"5.3": {
  "name": "单元",
  "content": "按照 5.3.1 的方式描述所有软件单元的设计。",
  "subsections": {
    "5.3.1": {
      "name": "词法分析器",
      "content": "该软件单元完成源代码字符流到记号流的转换，标识符 Lexer。",
      "subsections": {
        "5.3.1.1": {
          "name": "入口函数",
          "content": "该软件单元的入口函数如下。",
          "blocks": [
            { "type": "table", "prototype": "entry_func", "caption": "表5-X 词法分析器入口函数",
              "data_start_row": 0, "preserve_tail_rows": 0,
              "rows": [ { "item": "单元名称", "content": "词法分析器" }, { "item": "入口函数", "content": "int Lexer_Scan(void)" } ] }
          ]
        },
        "5.3.1.2": {
          "name": "输入输出",
          "content": "该软件单元的输入输出数据描述如下。",
          "blocks": [
            { "type": "table", "prototype": "io_data", "caption": "表5-X 词法分析器输入输出数据",
              "data_start_row": 1, "preserve_tail_rows": 0,
              "rows": [ { "number": "1", "name": "源代码字符流", "identifier": "src", "type": "string", "length": "-", "direction": "IN", "description": "待分析的源程序文本" } ] }
          ]
        }
      }
    }
  }
}
```

**静态章节**（1 / 2 / 4 / 6 / 8 的表，3 / 7 的正文）：把 `rows` 直接写进对应 `tables[]`（`locator_rows`/`columns` 不动），或把正文写进 `content`。第 4 章 `tables` 只填 4.3.1 的外部/逆向接口清单表；4.1/4.2 已改为动态章节。

- `rows` 中每行的字段集合必须严格等于 `columns` 定义；单元格同样**不得为空**。
- `locator_rows` 必须与模板表头文本**完全一致**，不得修改。
- **标题 / 题注交给 Word**：目录是 Word 域，题注编号由引擎按章号重写。
