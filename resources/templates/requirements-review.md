# {项目名称} 需求质量检查报告

> 编写规则（务必遵守，与本模板配套使用）：
> 1. 只报告问题，**不给最终裁决**；每条给出「建议处理方向」，由用户确认、修订或驳回。
> 2. **不得改写或覆盖用户已确认的内容**；本报告只作提示。
> 3. 每条问题必须有稳定的来源位置（文件、章节，能给出条目编号就给出）。
> 4. 问题类型只能取自固定检查目录（歧义 / 表达不完整 / 不可验证 / 指标缺失 / 来源引用缺失 / 重复 / 冲突 / 同一指标取值不一致 / 术语不一致 / 接口字段定义不一致）。
> 5. 检查顺序：先逐条检查，再跨条目检查。问题为空时如实填写「无」。
> 6. 凡无法从输入材料确定的内容，写「待补充」，不得臆造。
